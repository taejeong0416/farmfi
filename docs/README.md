# 문서 규칙

이 repo의 `docs/`를 다룰 때 따르는 규칙.

## 규칙

- 파일명은 영문 kebab-case (`feature-spec.md`).
- 문서를 수정하면 개발 단위로 커밋한다.
- 문서는 두 종류로 나눠 다룬다.
  - **레퍼런스** (현재 상태만): 제자리에서 수정하고 낡은 내용은 지운다. 날짜별 사본을 만들지 않는다 (이력은 git history).
  - **기록**: `dev-log.md` — 무엇을 했고 왜 그렇게 결정했는지 남기는 작업 기록. 최신을 맨 위에 쓰고, 오래되거나 끝난 항목은 자유롭게 압축·정리한다. 변경의 정확한 이력은 git이 보관하므로 완전한 연대기로 유지하려 애쓰지 않는다.
- 새 문서를 추가하면 아래 표에 한 줄 등록한다.

## 문서 목록

| 파일 | 내용 | 종류 |
|---|---|---|
| `feature-spec.md` | 웹 기능명세서 — STO 청약·검증·정산 (유일 정답 문서) | 레퍼런스 |
| `user-flow.md` | 웹 유저플로우 — 역할별 화면 이동 경로 | 레퍼런스 |
| `app-feature-spec.md` | 운영자 앱 기능명세서 — 매장 운영·생육·재고·매출 | 레퍼런스 |
| `app-user-flow.md` | 운영자 앱 유저플로우 — 화면 이동 경로 | 레퍼런스 |
| `dev-log.md` | 진행상황·결정 기록 | 기록 |

# FarmFi (팜피)

토큰증권(STO)을 활용한 **미니팜 자금집행 웹플랫폼**

도심 유휴공실을 스마트팜 기반 24시간 신선매장으로 전환하고, 그 전환 자금을 STO로 조달하며,
스마트컨트랙트 **마일스톤 게이트**가 **AI 검증 결과에 연동해 자금을 단계 집행**한다.

### 1. 프로젝트 소개

#### 1.1. 개발배경 및 필요성

- **부산대 앞 상권 공실은 3년째 회복되지 않는다**
  - 부산대 상권 소규모 상가 공실률 18.8%로 부산 평균(7.8%)과 전국 평균(8.3%)의 두 배를 넘고, 전국 5위·부산 1위다 (한국부동산원, 상업용부동산 임대동향조사, 2026년 1분기)
  - 25.6% → 23.4% → 25.2% → 18.8% → 18.8%로 3년째 높은 수준에 머물러 있다.
  - 주력 업종이 온라인으로 대체되면서 오프라인 매장의 존재 이유가 사라진 것이 원인이다. 유동인구가 아니라 **반복적으로 돈을 쓸 업종**이 사라졌다.

- **전환 업종은 세 조건을 동시에 충족해야 한다**

  | 조건 | 요구사항 | 근거 |
  |:---|:---|:---|
  | 입지 | 인구 밀집 상권의 생활권 수요 | 지속적 현금흐름 창출 |
  | 품목 | 소비 매체가 온라인으로 전환되기 어려운 업종 | 신선·즉시성 |
  | 구조 | 좁은 공간에서 높은 마진을 얻는 재배·판매 일체형 | 자립적 수익 창출 |

  스마트팜 기반 신선식품 매장이 이 세 조건을 모두 만족한다. LED로 24시간 가동되므로 무인 판매를 결합하면 추가 인건비 없이 24시간 초신선 매장이 성립한다.

- **수요는 확인됐지만 기존 채널이 못 받는다** (자체 설문, N=107, 2026.07.15–18)
  - 이런 매장이 생기면 주 1회 이상 이용하겠다 **42.1%**
  - 스마트팜에서 재배한 신선채소 구매 의향 **86.9%**
  - 최근 1개월 내 저녁·야간에 채소·과일이 필요했던 경험 **41.1%**, 그중 **90.9%가 바로 해결하지 못했다** (참음 43.2% / 새벽배송으로 다음날 29.5% / 다음날 구매 18.2%)
  - 배달·새벽배송 주 구매자의 **85.7%가 배달비·최소주문금액에 불만족** (N=14)

- **그러나 스마트팜 창업의 진입장벽은 높다**
  - 사이트당 설비 자본이 수천만 원 규모다. 개인이 혼자 넘기 어렵다.
  - 조각투자로 자금을 모을 수 있지만, 조각투자 시장에는 "고수익 홍보 → 자금 유용·부실 검증"의 신뢰 문제가 반복된다.
  - 세 문제의 교차점: **자본은 검증을 요구하고, 검증은 코드로 강제할 수 있다.**

#### 1.2. 개발 목표 및 주요 내용

FarmFi는 투자자와 공실 운영자를 연결해, 공실을 스마트팜 기반 신선식품 매장으로 전환하는 데 필요한 인프라를 제공한다. 투자자 모집부터 운영자 관리까지 전 과정을 대행하는 운영 서비스이며, 이번 산출물은 그 인프라의 **자금집행 웹플랫폼 + 운영자 앱 MVP**다.

```
투자자 모집 → 운영자 모집 → 재배 → 판매 → 매출 분배
```

| 계층 | 기능 |
|:---|:---|
| 자금 조달·집행 | STO 청약, 투자금 분리보관, 마일스톤 트랜치 단계 집행, 회수금 분배 |
| 검증 | AI 멀티시그널 마일스톤 검증(계약서·영수증·현장사진·검수확인서·IoT), 교차검증, 온체인 기록 |
| 신원 | OpenDID 모바일 신분증 기반 실명·연령·투자한도 판별 |
| 운영 연동 | 운영자-공간 배정, 생육 모니터링, 재고-생육 연동, 판매-재배 연동 |
| 성과·확장 | 기관 성과 리포트, 다지점 관리 |

> FarmFi의 핵심은 **사람의 판단이 아니라 검증된 데이터와 코드가 자금 흐름을 통제한다는 것**이다. AI 검증이 통과하지 않으면 트랜치가 집행되지 않으며, 강제 통과 경로는 존재하지 않는다.

#### 1.3. 세부내용 — 이해관계자

| 주체 | 제공 가치 | 획득 가치 |
|:---|:---|:---|
| 투자자 | 초기 조성비·설비비 지원 | 원금 회수와 배당 수익 |
| 시니어 운영자 | 작물 재배·포장·품질관리, 매장 운영 | 운영 인프라·판매 시스템, 지속 가능한 수익과 일자리 |
| 소비자 | 수요 데이터 | 언제든 필요한 만큼 살 수 있는 신선식품 |
| 기관·건물주 | 유휴공간 제공 | 공실전환 성과 리포트 |

**투자자 관점** — 페르소나: 박현우 · 38 · 부산 직장인. *"목돈은 없고 코인은 불안하고, 실물 담보 있는 소액투자를 원한다."*

| | 조건 |
|:---|:---|
| 함께 투자 | 매장 한 곳의 설비 조성비 8,000만 원을 여럿이 나눠서, 1구좌 1만 원 단위로 |
| 지분만큼 배당 | 매장이 파는 만큼, 보유 구좌 비율대로 매달 배당 (전체의 10% 보유 시 월 약 49만 원) |
| 원금 + 수익 | 연 프리미엄 6\~12% × 회수기간 12\~30개월 조합에서 선택. 기본 투자안은 연 6% · 24개월 |
| 안전장치 | 매장 수익이 나지 않으면 회수기간을 최대 36개월까지 연장하고, 설비 처리대금의 90%를 투자자에게 지급 |
| 엑싯 | 원금 + 프리미엄을 다 회수하면 배당 종료 |

투자안은 매장이 감당해야 할 **하루 필요 판매량**으로 환산되고, 유닛 생산 기준선(26팩/일) 대비 신호등으로 개설 가능성을 판정한다 — 22팩 이하 개설 권장 / 23\~26팩 투자자 공지 후 개설 / 27팩 이상 개설 불가. 기본 투자안(연 6% · 24개월)은 22팩/일이다.

**운영자 관점** — 자체 설문(N=13, 2026.07.15–18)에서 업무 내용과 수익 구조를 숙지한 이후의 실질 참여 의사가 확인됐다.

#### 1.4. 기존 서비스 대비 차별성

| 비교 항목 | 일반 조각투자 | 일반 스마트팜 SW | 일반 POS | **FarmFi** |
|:---|:---|:---|:---|:---|
| 자금 집행 | 일괄 지급 | 해당 없음 | 해당 없음 | **마일스톤 단계 집행** |
| 집행 근거 | 운영사 판단 | 해당 없음 | 해당 없음 | **AI 다중신호 검증 + 온체인 기록** |
| 관리 대상 | 자금만 | 재배만 | 판매만 | **재배 ↔ 판매 ↔ 자금 연결** |
| 투자자 보호 | 약관 의존 | 해당 없음 | 해당 없음 | **데드라인 타임아웃 · 비례 환불 · 배당 스냅샷** |
| 기관 보고 | 없음 | 없음 | 없음 | **공실전환·생산·판매 성과 리포트** |

### 2. 상세설계

#### 2.1. 시스템 구성도

```
[ 사용자 채널 ]
   투자자·구매자 웹  (Next.js 14 App Router)
   운영자 앱        (Expo React Native)
        │
        │  HTTPS · 세션 — 웹은 쿠키, 앱은 Bearer
        ▼
[ FarmFi 서버 — Next.js API Routes (Vercel) ]

   신원·자격     OmniOne CX 본인확인 → OpenDID Verifier
                 → 실명·연령·투자한도 판별 / 운영자 보증서(VC) 발급
   자금·집행     청약 게이트 → 에스크로 분리보관 → 5단계 트랜치 → 설비업체 직불
   AI 게이트     Gemini Vision·OCR — 계약서·영수증·현장사진·검수확인서
                 문서 간 교차검증 → 통과분만 집행. 강제 통과 경로 없음
   운영·최적화   생육 모니터링 · 재고-생육 연동 · 판매-재배 최적화 · 생육 레시피
   정산·지급     매출 확정 → 워터폴 분배 → 지급 어댑터
   기록 중계     Outbox → Chain Relay (운영지갑이 서명)
        │
        ├─▶ [ 데이터 ]     Supabase PostgreSQL — 계정·검증결과·보유 원장
        │                  Supabase Storage — 증빙 원본, SHA-256 해시로 대조
        │
        ├─▶ [ 외부 연동 ]  토스페이먼츠 — 가상계좌 발급 · 입금 통지 웹훅
        │                  POS · IoT 센서 — 판매·생육 데이터 수집
        │
        └─▶ [ 기록 원장 ]  OmniOne Chain (BESU) — 가스 0, 운영지갑 서명
                           Escrow · FarmToken · Dividend · RoundGate
                           ProjectRegistry · AuditTrail
                           Custody Wallet — 1인 1지갑, AES-256-GCM 봉인
```

**원칙** — 원화는 금융기관 계좌에 보관하고, 블록체인에는 자금의 배정·집행·정산 **상태와 결과**를 기록한다. 투자자는 지갑 주소·개인키·가스비를 직접 다루지 않는다. 수탁 지갑을 서버가 만들고 관리하며, 키는 봉인해 보관한다.

#### 2.2. 자금 집행 구조

투자자가 많고 단계가 반복되면 사람이 직접 관리하는 데 한계가 있다. 승인 지연·오류·사람 개입 리스크를 없애기 위해, 자금 보관과 조건 검증을 스마트컨트랙트에 맡긴다.

```
자금 입금 → 분리보관(신탁) → 조건 검증 → 마일스톤 게이트 통과 시 단계별 집행 → 참여자 회수
```

**마일스톤 트랜치와 검증 신호**

| 단계 | 집행 비율 | 누적 | 검증 신호 |
|:---|---:|---:|:---|
| M1 계약 체결 | 10% | 10% | 공간사용 협약서 · 임대계약서 |
| M2 설비 발주·제작 | 20% | 30% | 설비 발주서 · 계약금 영수증 (교차검증) |
| M3 반입·설치 착수 | 30% | 60% | 반입 현장 사진 · 운송 영수증 (교차검증) |
| M4 설치 완료·검수 | 25% | 85% | 설치 완료 사진 · 검수확인서 (교차검증) |
| M5 시운전·영업 개시 | 15% | 100% | 센서 데이터 (가동률) · 첫 판매 영수증 |

비율은 리스크가 실제로 이동하는 시점에 맞춰 잡았다. 계약 단계는 낮게 두어 투자자 노출을 줄이고, 하드웨어가 현장에 들어오는 반입 시점(누적 60%)에 대금을 크게 실어 설비업체의 외상 구간을 좁힌다. 마지막 15%는 실제 개점까지 확인하는 유보금이다.

**지급은 에스크로에서 설비업체로 직불된다.** 운영자는 현금을 선지급하지도, 집행액을 경유해 만지지도 않는다. 증빙은 운영자(현장 사진)와 설비업체(발주서·검수확인서)가 나눠 제출해 한쪽 단독으로는 위조가 성립하지 않는다.

각 마일스톤에는 데드라인이 있고, 경과 시 **누구나 실패 전환을 트리거해 환불 모드로 넘길 수 있다.** 운영사의 선의에 의존하지 않는 투자자 탈출구다.

**집행과 정산은 분리된다.** 마일스톤(증빙 기반)은 매장 *조성자금 집행*에만 적용하고, 투자수익은 매장 *운영실적과 투자 비율*을 기준으로 별도 정산한다. 조성이 끝난 매장의 배당이 증빙 검증에 묶이지 않는다.

**참여자 안전장치** — 세 주체가 서로 다른 축으로 묶여 어느 한쪽이 다른 쪽을 일방적으로 잡지 못한다.

| 주체 | 장치 |
|:---|:---|
| 투자자 | 마일스톤 게이트 · 데드라인 타임아웃 · 비례 환불. 수익 부진 시 회수기간 최대 36개월 연장 + 설비 처리대금 90% 지급 |
| 설비업체 | 대금 완납 전까지 설비 소유권 유보 — 중단 시 모듈형 유닛을 회수해 재판매·재배치. 미집행 에스크로 잔여는 미회수 대금 보전에 우선 배정 |
| 운영자 | 현금 자기부담 없음 — 노동·성과연동 보수·운영보증서로 책임을 진다. 이탈 시 설비를 철거하지 않고 교육·보증서를 마친 대기 운영자 풀에서 교체 |

**단계별 투자와 토큰 가치**

라운드가 진행될수록 흑자 전환까지 남은 시점이 짧아지고 리스크가 줄어, 토큰 가치가 상승한다. 초기 투자자일수록 우대되는 구조다.

| 단계 | 상태 | 리스크 | 토큰 가치 |
|:---|:---|:---|:---|
| 1단계 초기 구축 | 흑자 전환까지 먼 시점 | 가장 높음 | 가장 낮음 |
| 2단계 운영 검증 | 데이터 축적·입증 중 | 감소 시작 | 점진적 상승 |
| 3단계 흑자 근접 | 안정성 증가 | 감소 | 상승 가속 |
| 4단계 흑자 이후 | 반복 흑자·배당 가능 | 가장 낮음 | 가장 높음 |

**금융 구조 핵심 프로세스**

```
① 생산 (스마트미니팜 작물 생산)
   → ② 판매 (24시간 무인매장 · B2B 인근 가게)
   → ③ 매출 발생 (안정적 매출 지속)
   → ④ 정산 (월 단위 집계)
   → ⑤ 참여자 회수 (조건별 분배)
   → ⑥ 재생산 (회수 자금으로 지속 운영·재투자)
```

#### 2.3. 신원·자격 검증

사용자 입력이나 서류 사진이 아니라, **위조가 불가능한 국가 신원으로 청약 자격을 자동 판별**한다. STO 청약은 실명·연령·투자한도 확인이 자본시장법상 의무이며, 익명 지갑과 증권 보유자 식별을 결합해야 양도 제한과 자금세탁방지 요건을 충족할 수 있다.

```
OmniOne CX 표준인증창 호출 (QR/딥링크)
  → 전자지갑 신분증 제출 (eVP)
  → VC · Verifier 검증
  → JWT 파싱
  → 실명 · 연령(성인) · 투자한도 판별
  → 청약 승인
```

| 구현 기술 | 내용 |
|:---|:---|
| OmniOne ID 검증 SDK | 조폐공사 K-DID 공개 SDK 기반 VP 제출·검증 |
| VC Selective Disclosure + 투자한도 룰엔진 | 실명·만 18세 이상·투자한도만 선택 추출 → 자본시장법 적격 투자자 검증 |
| DID ↔ 지갑주소 온체인 바인딩 | 토큰 컨트랙트의 신원 레지스트리에 지갑↔DID 해시를 등록해 보유자 식별 |

```

        ↓

        ↓
[6] 트랜치 자동 집행 — 에스크로 → 설비업체 직불

        ↓

        ↓

```

#### 3.5. AI 도구 활용

**제품 내장 AI — 자금 집행의 게이트**

AI는 단순 API 호출이 아니라 자금 집행의 게이트 역할을 한다. 증빙(계약서·영수증·현장사진·검수확인서)을 수집해 AI가 판독하고 문서 간 상호 교차검증을 거친 뒤, 판정 결과에 따라 트랜치 집행과 보류로 분기한다. **검증 실패 시 트랜치는 집행되지 않으며 강제 통과 경로는 없다.**

| AI 기능 | 내용 | 기대 효과 |
|:---|:---|:---|
| 마일스톤 증빙 검증 | Gemini 비전·OCR로 계약서·영수증·현장사진·검수확인서 판독 후 교차검증 | 자금 유용 차단, 검증 기준의 재현성 확보 |
| 검수확인서 판독 | 합격 여부와 하자 목록을 추출해, 하자가 남으면 사진이 멀쩡해도 집행을 막는다 | 서류만 앞선 완료 처리 차단 |
| 생육 이상 탐지 | 센서 데이터 Z-score + 도메인 정상범위(수직농장 상추 문헌 기반) 판정 | 지속성 고장·스파이크 이상 조기 감지 |
| 판매-재배 최적화 | 품목별 판매 추이 분석 → 다음 재배 사이클 증산/감축 추천 | 안 팔리는 작물 과잉생산 방지 |
| 생육레시피 | 환경↔수율 반응표면 학습 → 수익 최적 환경조건 도출. 문헌·다른 품종·자체 데이터를 정밀도로 합성하고 불확실성을 구간으로 낸다 | 비전공 운영자 진입장벽 완화 |
| 운영 브리핑 | 상황을 보고 필요한 분석 도구를 골라 실행 (LLM 하네스) | 오늘 할 일을 문장으로 |

`납입 → 발행 → 증빙 → 검증 → 집행 → 정산 → 지급` 전 과정이 실제로 동작한다. `demo/reset`·`demo/step` 8단계로 통주행 시연할 수 있고, 각 구간을 실물로 확인했다.

| 구간 | 확인한 것 |
|:---|:---|
| 투자금 납입 | **토스페이먼츠**가 실제로 가상계좌를 발급한다(우리은행). 입금 통지 웹훅은 계좌별 `secret` 대조로 검증한다 |
| 보유 구좌 발행 | 입금 확인과 **같은 트랜잭션**에서 발행을 예약하고 Chain Relay가 체인에 올린다. **OmniOne Chain(BESU)에 920구좌 발행 확인** |
| 원장 대사 | DB 920구좌 ↔ 체인 920구좌, **불일치 0건** |
| 증빙 → 집행 | 실 Gemini로 계약서·영수증·사진을 교차검증하고, **증빙이 승인된 단계만** 트랜치가 나간다. 단계는 순서대로만 집행된다 |
| 정산 → 지급 | 관리자가 매출·비용을 **확정해야** 회수금 계산이 돈다. 지급은 어댑터를 타되 실제 이체는 지급대행 계약 전까지 Mock이며 화면에 그대로 표기한다 |

멱등성도 실측했다. 같은 입금 통지를 3회 보내도 입금 이벤트 1건·발행 1건이고, 같은 픽업 바코드는 두 번 처리되지 않는다.

### 4. 설치 및 사용 방법

**필요 소프트웨어:** Node.js 20+, Git

```bash
$ git clone https://github.com/PNU-2026-AI-Hackathon/pnuai-b-01-b301.git
$ cd pnuai-b-01-b301/frontend
$ npm install
$ cp .env.example .env          # DATABASE_URL, JWT_SECRET, GEMINI_API_KEY
$ npm run prisma:generate
$ npx prisma db push --url "<세션 pooler 5432 URL>"   # DB 스키마 반영
$ npm run seed                  # 시드 (지점·품목·재고·수확·판매·IoT·STO)
$ npm run dev                   # http://localhost:3000
```

> 스키마 반영(DDL)만 **세션 pooler(5432)** 로 해야 한다. `.env`의 `DATABASE_URL`은 트랜잭션 pooler(6543)라 `prisma db push`가 거기서는 통하지 않는다. 런타임과 시드(DML)는 6543 그대로 쓴다.

운영자 앱을 띄우려면:

```bash
$ cd app && npm install && npx expo start
```

컨트랙트를 빌드·테스트하려면:

```bash
$ cd contracts && git submodule update --init && forge test
```

**환경 변수 (.env):** 자세한 키 목록은 [CONTRIBUTING.md](CONTRIBUTING.md) 참고. 최소 구동은 `DATABASE_URL` · `JWT_SECRET` · `GEMINI_API_KEY`면 되고, 온체인·신원인증 키가 없으면 해당 기능이 비활성으로 떨어진다.

시드 로그인 계정: `operator@farmfi.test` / `admin@farmfi.test` (비밀번호 `farmfi123`)

**신규 합류자는** [docs/service-plan.md](docs/service-plan.md)(기획 정본)를 먼저 읽고, [docs/feature-spec.md](docs/feature-spec.md)(웹)와 [docs/app-feature-spec.md](docs/app-feature-spec.md)(앱)로 기능 범위와 화면 흐름을 파악하면 된다.

### 7. 해커톤 참여 후기

- **이정서**
  > 짧은 시간이었지만 스마트팜 산업을 깊이 들여다보고, 블록체인과 스마트컨트랙트의 활용 방안을 고민하면서 새로운 투자상품까지 직접 고안해 볼 수 있었습니다. 하나의 아이디어를 사회·경제·기술의 관점에서 구체화하며 많이 배우고 성장한 시간이었습니다.

- **조원진**
  > UI/UX를 배워본 적은 있지만, 기획자, 개발자분들과 협업하는 것은 처음이라 제가 설계한 화면과 기능이 실제 개발 과정에서도 적절한지 확신이 서지 않아 고민했던 순간도 많았습니다.
  >
  > 여러 시행착오를 직접 겪으며 기획이 디자인으로, 디자인이 개발로 어떻게 연결되는지 몸소 배울 수 있었고, 클로드 MCP와 같은 새로운 도구를 활용하는 경험도 쌓을 수 있었습니다. 이 경험을 자양분 삼아 앞으로도 익숙하지 않은 분야더라도 두려워하지 않고, 도전하며 배우는 태도를 이어나가고 싶습니다.

- **우민성**
  > 이번 해커톤을 통해 평소 접해보지 못했던 블록체인 기술을 실제 프로젝트에 적용해보는 경험을 할 수 있었습니다. 또한 AI를 단순히 사용하는 것을 넘어, AI와 함께 코드를 작성하고 수정하며 서비스를 구현하는 새로운 개발 방식을 경험할 수 있어 의미 있었습니다.

- **박태정**
  > 규모 있는 서비스의 개발을 맡아 보며, 어려운 것은 기능을 만드는 일이 아니라 만들어 둔 기능들이 서로 어긋나지 않게 하는 일이라는 것을 배웠습니다. AI가 발전하면서 만드는 속도는 빨라졌지만 그만큼 결정하고 검증하는 능력이 더 중요해졌다고 느낍니다.
